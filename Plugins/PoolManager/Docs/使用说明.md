# Pool Manager 使用说明

对象池插件，用于复用高频创建/销毁的对象（投射物、特效、UI 控件等），避免频繁 spawn/destroy 造成的卡顿。

适用引擎版本：UE 5.7。插件默认启用（`EnabledByDefault`），模块加载阶段为 `EarliestPossible`。

---

## 一、核心概念

### 1.1 职责划分

| 角色 | 类型 | 职责 |
| --- | --- | --- |
| `UPoolManagerSubsystem` | World Subsystem | **只管数据**：维护每个类对应的 Pool、对象的激活状态、句柄映射 |
| `UPoolFactory_UObject` 及其子类 | UObject | **只管行为**：如何创建、销毁、隐藏/显示某一类对象 |
| `FPoolContainer` | 结构体 | 一个类对应一个池，持有该类的所有对象数据与所属 Factory |
| `FPoolObjectData` | 结构体 | 描述池中单个对象：对象指针、是否激活、句柄 |
| `FPoolObjectHandle` | 结构体 | 对象的间接引用（GUID），对象未生成时也有效 |

需要自定义行为时，**重写 Factory，而不是重写 Pool Manager**。

### 1.2 对象状态（`EPoolObjectState`）

| 状态 | 含义 |
| --- | --- |
| `None` | 不由 Pool Manager 管理 |
| `Inactive` | 在池中，空闲，可被取出 |
| `Active` | 已被取出，正在使用，可归还 |

### 1.3 内置 Factory 的池化行为

| Factory | 创建 | 销毁 | 归还到池时的处理 |
| --- | --- | --- | --- |
| `UPoolFactory_UObject` | `NewObject` | `ConditionalBeginDestroy` | 不做任何状态改变 |
| `UPoolFactory_Actor` | `SpawnActor`（延迟构造） | `Actor->Destroy()` | 移动到 `MaxPos`（约 ±1048576）、`SetActorHiddenInGame`、关碰撞、关 Tick |
| `UPoolFactory_UserWidget` | `CreateWidget` | 递归销毁子控件 + `RemoveFromParent` + `ConditionalBeginDestroy` | `SetVisibility(Collapsed)` |

> Actor 之所以被移到极远处而不是仅关碰撞，是因为 `SetCollisionEnabled` 不会被网络复制，客户端仍会与隐藏的 Actor 发生碰撞。

## 二、快速开始（C++）

```cpp
#include "PoolManagerSubsystem.h"
#include "Data/PoolObjectData.h"
```

### 2.1 取出单个对象

```cpp
// 模板版：适合 C++ 类
const FPoolObjectHandle Handle = UPoolManagerSubsystem::Get().TakeFromPool<AProjectile>(
    SpawnTransform,
    [](const FPoolObjectData& Data)
    {
        AProjectile& Projectile = Data.GetChecked<AProjectile>();
        Projectile.Launch();
    });

// 传类版：适合蓝图类
UPoolManagerSubsystem::Get().TakeFromPool(BlueprintProjectileClass, SpawnTransform, Completed);
```

回调 `Completed` 的触发时机分两种情况：

- 池中**有**空闲对象 → **同步立即**回调，`TakeFromPool` 返回时对象已可用；
- 池中**没有**空闲对象 → 请求入队，在**后续帧**生成后才回调（除非用 `Critical` 优先级）。

因此不要假设回调一定异步，也不要假设一定同步。

### 2.2 只取现成的，不新建

```cpp
// 池中没有空闲对象时返回 nullptr，不会创建新对象
const FPoolObjectData* Data = UPoolManagerSubsystem::Get().TakeFromPoolOrNull(AProjectile::StaticClass(), Transform);
```

> 返回的指针指向池内数组元素，**用完即取值，不要长期持有**：后续对池的增删可能导致数组重分配而使指针失效。

### 2.3 批量取出

```cpp
TArray<FPoolObjectHandle> Handles;
UPoolManagerSubsystem::Get().TakeFromPoolArray(
    /*out*/ Handles,
    AProjectile::StaticClass(),
    /*Amount=*/ 20,
    [](const TArray<FPoolObjectData>& Objects)
    {
        // 全部就绪后回调一次
    });
```

需要不同类、不同 Transform 混合请求时，用 `FSpawnRequest` 数组的重载：

```cpp
TArray<FSpawnRequest> Requests;
FSpawnRequest Request(AProjectile::StaticClass());
Request.Transform = Transform;
Request.Priority = ESpawnRequestPriority::High;
Requests.Emplace(MoveTemp(Request));

TArray<FPoolObjectHandle> Handles;
UPoolManagerSubsystem::Get().TakeFromPoolArray(/*out*/ Handles, Requests, Completed);
```

### 2.4 归还

```cpp
UPoolManagerSubsystem::Get().ReturnToPool(Projectile);   // 按对象
UPoolManagerSubsystem::Get().ReturnToPool(Handle);       // 按句柄
UPoolManagerSubsystem::Get().ReturnToPoolArray(Objects); // 批量
```

**优先用句柄归还**。按句柄归还是句柄独有的能力：如果对象归还得比生成还快（还在生成队列里），会直接**取消该生成请求**，避免生成出一个立刻就要销毁的对象。按对象归还做不到这一点，因为那时你根本还拿不到对象指针。

重复归还同一个已处于 `Inactive` 的对象是安全的空操作。

## 三、蓝图用法

### 3.1 节点

- **Take From Pool**：取单个对象，输入 `ObjectClass` / `Transform` / `Priority`
- **Take From Pool Array**：批量取，输入 `ObjectClass` / `Amount` / `Priority`
- **Return To Pool** / **Return To Pool Array**
- 节点分类：右键菜单 → `Pool Manager`

两个 Take 节点的输出引脚会**根据 `ObjectClass` 选中的类自动变型**，无需再手动 Cast。

执行输出有两个：

| 引脚 | 触发条件 |
| --- | --- |
| `Completed` | 取到有效对象（数组版：数组非空） |
| `Failed` | 返回 null / 空数组，例如类无效、生成失败、`Amount` 为 0 |

### 3.2 蓝图侧的三条硬性限制

1. **只能放在事件图表（Event Graph）**，不能放在函数或普通宏里 —— 它内部会展开出 Custom Event 节点。
2. **不要在 for/while 循环里逐个调用 Take From Pool**，`Completed` 输出在循环中不会按预期工作。需要多个对象请用 **Take From Pool Array**。
3. 该节点由 `K2Node_TakeFromPool` 实现，**不能被重写**。

### 3.3 获取 Pool Manager

- `Get Pool Manager`：拿默认的 Pool Manager
- `Get Pool Manager By Class`：拿自定义子类的 Pool Manager

## 四、优先级（`ESpawnRequestPriority`）

| 优先级 | 行为 | 适用场景 |
| --- | --- | --- |
| `Normal` | 追加到队列末尾 | 默认，绝大多数情况 |
| `Medium` | 插到所有 `High` 之后、`Normal` 之前 | 略微提前 |
| `High` | 插到队列头部，下一帧处理 | 对延迟敏感的紧急激活；会推迟其他请求 |
| `Critical` | **当前帧同步生成**，完全不入队 | 绝不能有一帧延迟的场景 |

> `Critical` 是同步执行的，**禁止用于批量请求**，调用过多会直接造成 CPU 卡顿。

## 五、让对象自己感知池事件

实现 `IPoolObjectCallback` 接口即可，无需继承特定基类：

```cpp
UCLASS()
class AProjectile : public AActor, public IPoolObjectCallback
{
    GENERATED_BODY()

public:
    //~Begin IPoolObjectCallback Interface
    virtual void OnTakeFromPool_Implementation(const FTakeFromPoolPayload& Payload) override;
    virtual void OnReturnToPool_Implementation() override;
    virtual void OnChangedStateInPool_Implementation(EPoolObjectState NewState) override;
    //~End IPoolObjectCallback Interface
};
```

`FTakeFromPoolPayload` 提供两个字段：`Transform`（目标位置）和 `bIsNewSpawned`（是否为新生成而非复用）。

### 回调顺序

**新生成的对象：**

```
SpawnNow → OnPreRegistered（此时注册进池，不发通知）
         → OnPostSpawned
         → OnTakeFromPool（Payload.bIsNewSpawned = true）
         → OnChangedStateInPool(Active)
```

**从池中复用的对象：**

```
OnTakeFromPool（Payload.bIsNewSpawned = false，此时 Transform 已设置）
    → OnChangedStateInPool(Active)
```

**归还时：**

```
OnReturnToPool → OnChangedStateInPool(Inactive)
```

对 Actor 而言，`OnTakeFromPool` 被调用时 Transform 已经设置完毕，可以安全地读取位置做后续逻辑。

## 六、项目设置

路径：`Project Settings` → `Plugins` → `Pool Manager`
配置文件：`Config/BasePoolManager.ini`

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `SpawnObjectsPerFrame` | 5 | 每帧最多处理多少个生成请求，控制分帧生成速度 |
| `PoolFactories` | 三个内置 Factory | Pool Manager 启动时会实例化这里列出的所有 Factory |

对象的创建被刻意限制在**游戏线程 + 分帧**执行：在其他线程创建 UObject 并不线程安全，且会引发 GC 问题；分帧则是为了避免一次性生成大批对象造成卡顿。

## 七、扩展：自定义 Factory

适用于内置三类之外的对象（如 Component），或需要改变某类对象的池化行为。

```cpp
UCLASS()
class UPoolFactory_MyType : public UPoolFactory_UObject
{
    GENERATED_BODY()

public:
    virtual const UClass* GetObjectClass_Implementation() const override { return UMyType::StaticClass(); }
    virtual UObject* SpawnNow_Implementation(const FSpawnRequest& Request) override;
    virtual void Destroy_Implementation(UObject* Object) override;
    virtual void OnChangedStateInPool_Implementation(EPoolObjectState NewState, UObject* InObject) override;
};
```

步骤：

1. 继承 `UPoolFactory_UObject`（或 `UPoolFactory_Actor` 等更贴近的子类）
2. 重写 `GetObjectClass()` 返回负责的类
3. 加入 `Project Settings` → `Pool Manager` → `Pool Factories`

Factory 的匹配方式是**沿类继承链向上查找最近的已注册 Factory**。因此为 `AActor` 注册的 Factory 会自动接管所有 Actor 子类，而为某个具体子类注册的 Factory 优先级更高。

运行时也可增删：`AddFactory()` / `RemoveFactory()`，适合从其他插件或模块注册。

## 八、缓存上限（Pool Policy）

`UPoolFactory_UObject::MaxCachedInactive` 限制该 Factory 最多缓存多少个 **Inactive** 对象：

- 默认 `INDEX_NONE`（-1），即不限制；
- 超过上限后，再归还的对象会被**直接销毁**（先从池注册表移除，再调用 `Destroy`），而不是缓存；
- 它**只限制缓存数量**，不限制创建、生成，也不限制激活对象的数量。

> 该属性标记为 `Transient` + `VisibleInstanceOnly`，不会被序列化，也无法在细节面板或项目设置中编辑。要设置它，只能在自定义 Factory 子类的 C++ 构造函数中赋值。

## 九、清空池

```cpp
UPoolManagerSubsystem::Get().EmptyPool(AProjectile::StaticClass()); // 清空某一类
UPoolManagerSubsystem::Get().EmptyAllPools();                       // 清空全部
UPoolManagerSubsystem::Get().EmptyAllByPredicate(                    // 按条件清
    [](const UObject* Object){ return Object->IsA<AProjectile>(); });
```

`EmptyPool` 的完整行为：先丢弃该 Factory 队列中所有待处理的生成请求（避免池被移除后又被重建），再对激活中的对象补发一次 `OnReturnToPool` 以保证停用回调正常触发，然后销毁全部对象，最后连整个 `FPoolContainer` 一并移除。

以下两种情况**会自动清空，无需手动调用**：

- **编辑器切换关卡时**：编辑器实例与 PIE 实例生命周期不同，切图时自动清空以防内存泄漏；
- **Game Feature 插件停用时**：`UPoolManagerSubsystem` 实现了 `IGameFeatureStateChangeObserver`，会自动清空所有归属于该插件的类所对应的池。

## 十、状态查询

```cpp
UPoolManagerSubsystem& Pool = UPoolManagerSubsystem::Get();

Pool.GetPoolObjectState(Object);        // None / Inactive / Active
Pool.IsActive(Object);                  // 是否已取出
Pool.IsFreeObjectInPool(Object);        // 是否空闲可取
Pool.ContainsObjectInPool(Object);      // 是否被管理
Pool.ContainsClassInPool(Class);        // 该类是否已有池
Pool.GetFreeObjectsNum(Class);          // 空闲数量
Pool.GetRegisteredObjectsNum(Class);    // 注册总数
Pool.FindPoolObjectByHandle(Handle);    // 句柄 → 对象数据
Pool.FindPoolHandleByObject(Object);    // 对象 → 句柄
```

## 十一、进阶：纳管已有对象

已经由外部代码创建好的对象，可以事后纳入池管理：

```cpp
FPoolObjectData Data(ExistingActor);
Data.bIsActive = true; // 当前正在使用
UPoolManagerSubsystem::Get().RegisterObjectInPool(Data);
```

仅用于 Pool Manager 尚不知晓的已存在对象；正常流程中该函数由内部自动调用，无需手动干预。

## 十二、注意事项汇总

1. `UPoolManagerSubsystem::Get()` 内部是 `CastChecked`，**取不到会崩溃**。不确定时用 `GetPoolManager()` 并判空。
2. 所有池操作都在**游戏线程**执行，不要跨线程调用。
3. 对象归还后**不要再持有其引用**继续使用 —— 它随时可能被别处取走。
4. Actor 归还后被移到极远处且关闭了 Tick 与碰撞，取出时会重新设置 Transform 并恢复；依赖 `BeginPlay` 的初始化逻辑需要改到 `OnTakeFromPool` 里，因为复用不会再次触发 `BeginPlay`。
5. `TakeFromPoolOrNull` 返回的是**池内元素的裸指针**，随用随取，勿缓存。
6. `Critical` 优先级不可用于批量请求。
7. 蓝图 Take 节点只能放事件图表，且不可放进循环。
